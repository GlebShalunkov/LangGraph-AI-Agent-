# LangGraph AI Agent (деловая документация)

**Описание:** Локальный AI-агент на LangGraph + RAG, который отвечает на вопросы по уставу ООО.
Работает без интернета, не выдумывает информацию.

## 🎯 Что делает

Агент принимает вопрос на естественном языке и находит прямой ответ в тексте делового документа. Не нужно читать весь документ целиком — достаточно спросить.

Ключевое преимущество — **полностью офлайн**: локальная LLM (Ollama + qwen3:4b) и локальная векторная база (ChromaDB). Никаких API-ключей, подписок и передачи данных наружу.

## 🏗️ Архитектура

Граф LangGraph из двух узлов:

```
START → search_docs → call_model → END
```

**`search_docs`** — принимает вопрос, ищет релевантные фрагменты в векторной базе (ChromaDB, top-3), формирует контекст для модели.

**`call_model`** — принимает вопрос + найденный контекст, генерирует ответ строго по тексту документа.

**Почему два узла, а не один:**
- **Отладка:** видно, где именно ошибка — в поиске или в генерации
- **Гибкость:** можно заменить retriever или модель независимо друг от друга
- **Расширяемость:** легко вставить новые узлы (например, проверку релевантности) между существующими

## 🛡️ Защита от галлюцинаций

Реализована на трёх уровнях:

1. **Строгий промпт** — модели запрещено добавлять информацию вне контекста. Если ответа нет, она обязана написать «НЕТ ИНФОРМАЦИИ».
2. **Fallback при пустом поиске** — если retrieval ничего не нашёл, в контекст идёт явная заглушка «Документы не найдены» (иначе модель начнёт фантазировать).
3. **Низкая температура (0.1)** — минимум «творчества», максимум следования контексту.

## 🛠️ Стек

| Компонент | Технология | Зачем |
|-----------|-----------|-------|
| Оркестрация | LangGraph | Управление потоком «поиск → генерация» |
| LLM | Ollama + qwen3:4b | Локальная модель, без API |
| Векторная база | ChromaDB | Хранение и поиск эмбеддингов |
| Эмбеддинги | HuggingFace `paraphrase-multilingual-MiniLM-L12-v2` | Мультиязычные эмбеддинги |
| Фреймворк | LangChain | Обёртки для LLM, embeddings, vectorstore |

## 💡 Что умеет

- Ищет информацию в деловом документе
- Отвечает на вопросы по содержанию
- Честно говорит «нет информации», если данных нет

## 🚀 Как запустить

```bash
# 1. Установить зависимости
pip install -r requirements.txt

# 2. Запустить Ollama и скачать модель
ollama pull qwen3:4b
ollama serve

# 3. Запустить агента
python langgraph_rag.py
```

**Предусловия:** Python 3.10+, Ollama установлена, модель qwen3:4b скачана.

## 💬 Пример

**Вопрос:** «Кто участники общества?»

**Ответ:** «Иванов Иван Иванович (60%), Петрова Мария Сергеевна (40%)»

**Пример честного отказа:**

> **Вопрос:** «Какая у общества стратегия на 2027 год?»
> **Ответ:** «НЕТ ИНФОРМАЦИИ» — в уставе этого нет.

## ⚠️ Ограничения

- **Один документ.** База собрана по одному документу. Масштабирование на большой корпус требует пересмотра стратегии чанкинга и, возможно, гибридного поиска.
- **Нет истории диалога.** Каждый вопрос обрабатывается независимо.
- **Скорость.** Локальная модель qwen3:4b — компромисс между качеством и ресурсами. На слабом железе ответ может занимать десятки секунд.
- **Нет веб-интерфейса.** Пока только CLI.

## 🔮 Что можно улучшить

- **Скорость** — главный приоритет. Сложность в балансе: лёгкость по железу и памяти vs качество ответа.
- **Гибридный поиск** (BM25 + векторный) — лучше находит точные формулировки (имена, даты, номера).
- **История диалога** — уточняющие вопросы.
- **Веб-интерфейс** (Streamlit / FastAPI) — для демонстрации и интеграции.
- **Docker-упаковка** — запуск одной командой на любой машине.
